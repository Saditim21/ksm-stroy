## 2. Motion engine

### 2.1 Files and exports
- src/motion/engine.js (20 lines): the ONLY importer of `gsap`, `gsap/ScrollTrigger`, `gsap/SplitText`, `lenis`. Registers ScrollTrigger and SplitText, `ScrollTrigger.config({ ignoreMobileResize: true })`, default export `{ gsap, ScrollTrigger, SplitText, Lenis }` (:14-20). gsap 3.15.1. NO Flip anywhere.
- src/motion/runtime.js: `loadMotion()` memoised dynamic `import('./engine.js')` after window `load` (:24-34); `getMotion()` engine or null (:38-40); `scheduleInit(task)` idle queue, one task per `requestIdleCallback` (Safari: setTimeout 1), one `ScrollTrigger.refresh()` when the queue drains (:42-76). A throwing task does not stop the queue.
- src/motion/useMotion.js: `useMotion(scopeRef, setup, deps)`. `setup({ gsap, ScrollTrigger, SplitText, Lenis, lenis })` runs inside `gsap.context(..., scopeRef.current)` from the idle queue; the return value is a cleanup; unmount or dep change calls it and `ctx.revert()`. Does nothing unless `useMotionAllowed()`. Errors are rethrown after the context closes (:40-50). Comment contract: the markup is the final state, setups only animate FROM it (:13-16; spec §5.2.2: the first viewport never animates from JS).
  - Only consumer today: src/components/ui/DimensionLine.jsx. Everything else animated is legacy framer-motion or CSS.
- src/hooks/useMotionAllowed.js: `canAsk && !reduce && !saveData`; `canAsk` = matchMedia exists; `reduce` = useMediaQuery('(prefers-reduced-motion: reduce)'); `saveData` = navigator.connection.saveData. All via useSyncExternalStore with a server snapshot of false, so false on the server and while hydrating (:36-41). jsdom has no matchMedia, so tests are static by default.
- src/motion/SmoothScroll.jsx: wrapper `<div ref>` always rendered. When motion is allowed it loads the engine, builds Lenis with LENIS_OPTIONS and `virtualScroll: createGestureFilter()` (:63), publishes it via src/utils/lenis.js, `lenis.on('scroll', ScrollTrigger.update)`, drives it from `gsap.ticker` (`autoRaf:false`, `lagSmoothing(0)`), sets `html.dataset.motion = 'on'` (:77). A ResizeObserver on the wrapper re-measures Lenis and calls `ScrollTrigger.refresh()` once per frame (:92-115). Cleanup restores lag smoothing, removes the attribute, destroys Lenis (:117-125).
- src/utils/smoothScroll.js: LENIS_OPTIONS `{ lerp 0.07, wheelMultiplier 0.8, syncTouch false, allowNestedScroll true, autoRaf false }`; `createGestureFilter` leaves pinch and zoomed pan to the browser.
- src/utils/lenis.js: `getLenis()/setLenis/clearLenis` plus counted scroll locks `acquireScrollLock/releaseScrollLock` (stop on first, start on last, :34-69). `useScrollLock(background)` (src/hooks/useScrollLock.js) wraps them and sets html overflow and background.
- src/utils/motion.js: vocabulary without a GSAP import: `EASE_OUT 'expo.out'`, `EASE_IN_OUT 'expo.inOut'`, `EASE_FOLLOW 'power3'`, `LINE_STAGGER 0.1`, `CHAR_STAGGER 0.035`, `MD_UP '(min-width: 768px)'`, `CLIP_HIDDEN/CLIP_SHOWN` (:7-21). Spec §5.2.5 rules out generic parallax.
- src/utils/animations.js: LEGACY framer-motion variants. Spec §5.1: never combine framer-motion with the new engine; it leaves with the last legacy page.

### 2.2 The html.js gate (F1)
- Spec §6.3 and ledger:169: inline head script sets `html.js` unless reduced motion or Save-Data; CSS-only motion keys off it. Not implemented. Present instead: `data-motion="on"` (post-hydration, only while Lenis runs) and `motion-safe:animate-hero-rise` (HeroTitle.jsx:27, tailwind.config.js:172).
- Constraint: no attributes on `<html>`/`<body>` from scripts before hydration (spec §6.3; headScripts.js:5-9). screenHeight.js:14-17 writes a `<style id="screen-h">` into `<head>` instead, placed before the script itself (:21-27). The gate can follow that pattern (a head `<style>` that enables the motion CSS only when allowed), or put the class in Layout with suppressHydrationWarning. Ledger:169: "M2 Task 0 adds a variant keyed to html.js and moves HeroTitle and the route crossfade onto it".
- Head scripts today: SCREEN_HEIGHT_SCRIPT (screenHeight.js:27) at root.jsx:58; `--screen-h` kept current by `trackScreenHeight()` (root.jsx:128). Sections whose height sets page length use `--screen-h`, not vh/svh (screenHeight.js:3-5).

### 2.3 LenisScrollSync and the route transition boundary
- src/root.jsx:101-110 `RouteTransition`: `<ViewTransition key={normalizedPathname} enter="page-in" exit="page-out" default="none"><div><Outlet/></div></ViewTransition>`. Keyed by pathname, so a `?floor=` change does not transition. React 19.3 `<ViewTransition>`; RR runs navigations in a Transition. One persistent boundary was rejected (it would animate the "loading" commit and play twice on a cold nav; root.jsx:96-100, RR spike gotcha 9).
- src/index.css:318-321: `::view-transition-old(.page-out), ::view-transition-new(.page-in) { animation-duration: 260ms }` (browser default fade). :326-331 header group `site-header` (old hidden, new `animation:none`), so the header adopts the new page's look at once. :333-339 reduced motion kills every VT animation (media query only; Save-Data readers still get the crossfade, F1).
- Back/forward is instant (React does not animate popstate; spec §5.3).
- src/motion/LenisScrollSync.jsx (rendered after `<ScrollRestoration/>`, root.jsx:68-69): on `useLocation().key` change, in a layout effect, Lenis re-measures, a gliding fling is stopped, `scrollTo(y, { immediate:true, force:true })` so Lenis adopts the router's position before the VT snapshot (:44-66). Then `viewTransitionDone()` waits for the VT's own animations or `TRANSITION_MAX_MS = 350`, then `ScrollTrigger.refresh()` (:9, :16-21, :68-80).
- Absent today: shared-element transitions, any custom page transition, any `name=` on a ViewTransition, transition types, SplitText use, Flip. Spec §5.3 plans Home GR band -> GR hero as a shared element (`::view-transition-old/new(project-gr)`) and `update="none"` for same-route `?floor=`; none is built.

### 2.4 How a route-level two-door transition plugs in
- Where: only `RouteTransition` (root.jsx:101-110) and the CSS at index.css:314-339. The doors are two CSS animations on the `page-out` (old snapshot) and `page-in` (new snapshot) pseudo-elements, for example clip-path insets closing from left and right over the old page and opening on the new one, with an optional gold seam. No GSAP at the route boundary; spec §5.1 forbids a manual `document.startViewTransition`.
- Change list: (1) keyframes and duration at index.css:318-321; (2) raise `TRANSITION_MAX_MS` (LenisScrollSync.jsx:9) above the new duration plus margin, otherwise ScrollTrigger.refresh() fires mid-door and mis-measures (src/motion/LenisScrollSync.test.jsx pins the timing); (3) leave the `site-header` group rules so the header stays above the doors; (4) gate the doors on the html.js gate and keep the reduced-motion kill at :333-339; (5) doors only on some links would need React's per-type transition maps (`addTransitionType`); this repo does not use them, so verify against React 19.3.1 before relying on it, otherwise one transition for all routes.
- Carry: the old page stays until the new is ready (spec §5.3 "no blank frames": routes are prerendered; prefetch on intent is planned, but SiteHeader and Footer use plain `<Link to>` without `prefetch`, so add it); scroll reset stays in the layout effect before the new snapshot; useMotion reverts the leaving page's ScrollTriggers on unmount; move focus to `#main` after navigation (`tabIndex={-1}`, root.jsx:136; ledger:167 lists "focus/announce on route change").

### 2.5 SplitText and Flip
- SplitText is registered (engine.js:14) and passed to `useMotion` setups as `SplitText`; nothing uses it. Spec §5.1: at load split only the hero heading; other splits within about one viewport. check-dist fingerprints it (6.2).
- Flip is not installed. Spec §5.1: lazy, only in in-page viewers, <= 10 KiB gz. Add it as its own dynamic import, not into engine.js (the motion chunk is 52.5 KiB against the 60 KiB cap), and add a fingerprint to check-dist if it must stay out of first-load JS.
- Existing headline helper: `HeroTitle` (src/components/ui/HeroTitle.jsx) is CSS-only: `as` h1|h2, `lines[]`, each line in an overflow mask with `motion-safe:animate-hero-rise` and `--i` delay (60 ms steps). Markup is the final state. A SplitText H1 (the split diptych headline) would be a new component: full H1 text in the HTML, split post-hydration through `useMotion`.

### 8.2 api/odoo-lead.js (Vercel Function, Web Handler)
- Env: `ODOO_URL` (default `https://ksmstroy.odoo.com`, trailing slashes stripped, :16) and `ODOO_TEAM_ID` (default '1', :23). Timeouts: POST 8 s, health 5 s (:17-18).
- GET = health check: JSON-RPC `common.version` against `${ODOO_URL}/jsonrpc` (no auth, creates no record, :143-182). Answers 200 `{ ok:true, service:'odoo-lead', crm:{ reachable, version, teamId } }` or 503 `{ ok:false, … }`, always `Cache-Control: no-store, max-age=0` (:38-45, :191-197). An external monitor watches it; the form deliberately shows the visitor no CRM error.
- POST: JSON body only (else 400 `Invalid JSON body`); other methods 405 `Allow: GET, POST` (:199-211). It reads exactly six keys: `name`(<=200), `email`(<=250), `phone`(<=50), `projectType`(<=200), `budget`(<=100), `message`(<=5000), each trimmed and truncated; non-strings become '' (:26-33, :47-48, :222-229). Any other key (`company`, `source`, `project`) is IGNORED. There is deliberately NO honeypot: a `company` field was autofilled by browsers and real leads were dropped (main @fe406af, :217-221).
- Validation, 400 `{ ok:false, error:'Validation failed', fields:[…] }`: name >= 2 chars, email matches `/^[A-Z0-9._%+-]+@[A-Z0-9.-]+\.[A-Z]{2,}$/i`, message >= 10 chars (:50-64, :231-234). phone, projectType, budget optional.
- To Odoo: `POST ${ODOO_URL}/website/form/crm.lead` as `application/x-www-form-urlencoded`: `name` = „Запитване от сайта: <projectType|Общо запитване> — <name>“, `contact_name`, `email_from`, `description` = message, `phone` if any, `team_id` (so it is a Lead, not an Opportunity), custom fields `Тип проект`, `Бюджет` (default „Не е посочен“), `Източник` = „Форма за контакт - ksmstroy.com“ (fixed), `Изпратено на` (ISO) (:66-93). Odoo answers `{ id }`; the function returns 200 `{ ok:true, id }`, otherwise 502 `{ ok:false, error:'CRM unavailable' }` (:236-251).
- Pinned by tests/contracts/odoo-lead.test.js: default URL, ODOO_URL override, team 1 / ODOO_TEAM_ID, every field carried, empty optionals, trimming, field limits, non-string fields, no honeypot, 200 with id, 502 on error, 8 s timeout, GET health 200/503, never cached, 5 s health timeout, host from ODOO_URL.
