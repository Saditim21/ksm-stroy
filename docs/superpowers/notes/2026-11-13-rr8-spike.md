# Spike result: React Router 8 framework mode (ssr:false + prerender) for ksmstroy v2

## Verdict: GO, with conditions

Adopt it at the start of v2. Retrofitting later would cost more. All 11 listed routes prerender with real text, per-page `<title>`/description/canonical/OG and the hero `<img>`. Hydration is clean on all 11 in a production build, in a React-development build and under `react-router dev`. Client navigation, back/forward, live sheet data, Lenis, GSAP SplitLines and React 19.3 `<ViewTransition>` all work. The LCP request is now discoverable; on main it is not.

**Conditions.** Prerendering alone gives only a small Lighthouse gain (simulated LCP 4.92 → 4.67 s). The gain depends on three things:
1. Above-the-fold content must be in its final state in the HTML. framer-motion `initial` and opacity-until-onLoad patterns hid the whole hero until JS ran.
2. The hero must be designed around a Chrome LCP heuristic (gotcha 14). Otherwise the auto-advancing carousel makes LCP worse: 12 s with real throttling.
3. First-load JS (227 KB br) should be trimmed, because Lighthouse's simulation counts all JS that ran before the observed first paint.

Effort to apply to redesign-v2 is about 4 dev-days (range 3.5 to 5); breakdown at the end.

## Versions checked against docs and npm (2026-11-13)
- **react-router 8.5.1 is latest.** npm published it 2026-10-27, and reactrouter.com shows "latest (8.5.1)". 8.0.0 was published 2026-06-17.
- **v8 removes `react-router-dom`.** Import from `react-router`, or `react-router/dom` for `HydratedRouter`/`RouterProvider`. Minimums are node ≥22.22 and react/react-dom ≥19.2.7 (upgrade guide, plus `peerDependencies` and `engines` on npm). All confirmed.
- **React 19.3 made `<ViewTransition>` stable.** react.dev blog "React 19.3" (2026-09-09): "We shared it as an experimental API last year, and in 19.3 it's stable". It is `import { ViewTransition } from 'react'`, with props `enter`/`exit`/`update`/`share`/`default` plus `on*`. It only animates inside a Transition. Latest is react@19.3.1. Confirmed.
- **React Router view-transitions how-to (8.5.1).** The router wraps navigations in `startTransition` by default; do not set `useTransitions={false}`. The legacy `viewTransition` props are deprecated, and the page warns Back/Forward "may not animate".
  - The explanation page contradicts the how-to on whether `useNavigate` is wrapped. In my tests `useNavigate`, back and forward all animated, one transition each, in Chrome 157.
- **Vercel.**
  - Node 26.x (default), 24.x and 22.x are available. Node 20 is disabled for new deployments since 2026-10-01.
  - A range like `>=22` maps to the latest major (26.x). `.nvmrc` is not read.
  - Filesystem wins over rewrites.
  - `framework` slugs `vite` and `react-router` are valid in the vercel.json schema.

## Gotchas and their fixes
1. **The build silently runs `npm install isbot@5`** when there is no `entry.server` and isbot isn't a dependency. It edits package.json mid-build. In my `--legacy-peer-deps` tree this pruned 97 packages and broke node_modules. Fix: list `isbot` in dependencies.
2. **npm 11.4.2 crashes with `Cannot read properties of null (reading 'edgesOut')` on fresh resolution** (vitest's peer set). Clean `npm ci`, and `npm install` with the lockfile, both succeed. Fix: add packages with `--legacy-peer-deps`, then run a plain `npm install` to normalize the peers into the lock, and never drop the lockfile.
3. **`@react-three/fiber@9.5` blocks React 19.3** (its peer range is `react <19.3`). Bump to ^9.8.2; v2 drops three.js anyway.
4. **Prerender requests every path with a trailing slash** (`/about/`), while the browser hydrates `/about`. Navbar's `location.pathname === item.path` then differed, giving hydration error #418 on /about, /projects, /contact and /blog. Fix: `const pathname = location.pathname.replace(/(.)\/+$/, '$1')`. Applies to every pathname comparison.
5. **framer-motion `initial` is rendered into the HTML as inline `opacity:0`**, so the whole Home main, the hero image and the hero h1 were invisible until JS ran. Fix: `initial={false}` on the page wrappers (Home, About, Contact, About hero) and `<AnimatePresence mode="wait" initial={false}>` (3× in HeroCarousel). Rule for v2: final state in the HTML, and animate only after hydration.
6. **OptimizedImage starts at `opacity-0` until `onLoad`.** A prerendered image that loads before hydration never fires React's onLoad, so it stays invisible forever (verified: opacity 0 still at 4 s). Fix: `useState(priority)` so priority images start visible, plus a post-mount `img.complete && naturalWidth` check. Also `fetchpriority` → `fetchPriority`.
7. **Titles were set in an effect**, so every prerendered page had the default title. Fix: route `meta` exports. Pre-existing issues to fix in v2:
   - SEO appended "| KSM Stroy" twice.
   - Canonical and OG URLs use ksmstroy.bg, which doesn't resolve; the live domain is www.ksmstroy.com.
8. **The dev server found swiper, react-hook-form and others lazily**, then reported "optimized dependencies changed. reloading" mid-hydration. The page ended up with two React copies ("Invalid hook call") on the first visit to /about and /contact. Fix: the `optimizeDeps.include` list above.
9. **A persistent `<ViewTransition>` around the outlet also animated the router's "loading" commit** (route chunk not yet loaded) as a no-op cross-fade, then queued the real one. That was 2 transitions and about 810 ms click-to-settled on cold routes. Fix: the keyed enter/exit boundary, giving 1 transition and 455 ms.
10. **`html{scroll-behavior:smooth}` turned ScrollRestoration's `scrollTo(0,0)` into an animation**, and Lenis then pinned the start position, so the route change landed at Y=960. Lenis 1.3 only adds `lenis-smooth` while it is gliding, so the golden-residence override doesn't help when idle. Fix: remove the global rule.
11. **Vitest with the React Router plugin fails with a "preamble" error.** Fix: the VITEST guard plus `esbuild.jsx='automatic'`.

14. **Chrome 157 does not report a full-bleed hero `<img>` as an LCP candidate when it is painted before it finishes loading.**
