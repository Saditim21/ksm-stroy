# M1 baseline

What M2 to M4 start from: the M1 platform with the legacy pages still inside it. Measured on 2026-11-14 on `redesign-v2` (site code as of `8d3ba9c`). This is a baseline, not a pass or fail: the spec §10 budgets apply to the rebuilt pages.

## How it was measured

- **Build:** `npm run build`, a preview-stage build (robots `Disallow: /`, `noindex`). Its JS, CSS and HTML are otherwise those of a production build.
- **Server:** `node scripts/smoke/static-server.mjs` on `http://127.0.0.1:4190`. It applies `vercel.json` the way Vercel does and compresses text over 1 KiB (brotli quality 5). It serves HTTP/1.1, where Vercel's edge serves HTTP/2 and HTTP/3.
- **Lighthouse:** `npm run perf -- http://127.0.0.1:4190/ http://127.0.0.1:4190/projects/golden-residence/block-a`. That is Lighthouse 13.6.0 through npx with its default mobile settings, 3 runs per URL; the tables show medians. The defaults: a 412×823 screen at DPR 1.75, simulated slow 4G (150 ms RTT, 1.6 Mbit/s) and a 4× CPU slowdown.
- **"Bytes before LCP"** adds up the transfer size of every request the page started before the LCP was painted, in each run's own unthrottled trace.
- **Machine:** Windows 11, Node 22.23.4 (Vercel builds on Node 24; the spike found the build byte-identical), Chrome 157.0.8103.78.

**Why the motion chunk counts.** In the unthrottled trace the first paint comes after the load event:
- on `/`, FCP and LCP fall together at 355–396 ms, and the load event at 101–140 ms;
- on block-a, the paint at 189–248 ms and the load event at 80–141 ms.

The spike found the same: the first paint waits for the module scripts and hydration. The motion chunk is requested 23–37 ms after the load event, as designed (spec §5.1), so it lands before the paint and counts. On a phone the order can differ; the figure is an upper bound for this build.

## Seen along the way (for M2, not failures)

- **Two H1s on Home:** its visually hidden H1, plus the carousel's `motion.h1`. Spec §6.7 says one per page; M2 rebuilds Home.
- **Lazy EU logos:** both logos in the header's EU line have `loading="lazy"`, although every page shows them in the first viewport. Chrome reports a `LazyLoadImageIssue` for them. `ResponsivePicture` has no eager option short of `priority`, which also sets `fetchpriority="high"`.
- **Sheets on every page:** every legacy page reads the Google Sheets at hydration (`ApartmentProvider` in `root.jsx`). The smoke run therefore needs the network, and a sheet that fails to load logs a console error, which fails the run.
